# История разработки сайта MERANTI

Дата: 2026-08-02

## Задача

Создать новый сайт для бренда авторского шоколада MERANTI, вдохновлённый дизайном
kutkevich.ru (премиальный шоколадный бренд), но не являющийся прямой копией —
другое название бренда, свой контент, при этом с похожей эстетикой (тёмно-шоколадный
фон, золотые акценты, декоративная типографика).

## Ключевые решения по ходу работы

1. **Стек**: взят за основу проект `remont-site` (Next.js 14 + Tailwind CSS) —
   тот же скелет (форма заявки → Telegram, админка для редактирования контента,
   страницы privacy/oferta).

2. **Название бренда**: MERANTI — выбрано как благозвучное международное имя,
   отсылающее к ценной породе дерева (ассоциация с качеством и теплотой).

3. **Итерации дизайна**:
   - Первая версия — по текстовому описанию kutkevich.ru через WebFetch. Результат
     показался бедным/пустым по сравнению с оригиналом — не хватало визуального веса.
   - Вторая версия — добавлены секции с фото (галерея, карусель ассортимента,
     флагманский продукт), но структура ещё расходилась с оригиналом.
   - По скриншотам от пользователя пересобрана точная структура секций:
     Hero → USP (6 карточек) → "Для кого мы работаем" (аккордеон по 4 сегментам:
     отели, кофейни, ритейл, корпоративные) → Ассортимент (карусель) →
     Частным клиентам (маркетплейсы) → Галерея (грид фото) → Кейсы →
     Преимущества → О основателе → Отзывы → FAQ → CTA → Форма заявки.
   - Финальная точность — пользователь сохранил исходный HTML-код страницы
     kutkevich.ru (view-source) и передал в проект. Из него извлечены:
     - Точные цвета: золото `#C8A96E`, тёмный фон `#1C1006`, кремовый `#FAF8F4`
     - Точные шрифты: заголовки — `Poiret One` (тонкий декоративный),
       остальной текст — `Geologica` (300–500 вес)
     - Градиентная заливка золотого текста в заголовках
       (`linear-gradient(90deg, #E0D0AA → #C8A96E → #917040)` через
       `background-clip: text`) — именно это дало ощущение "роскоши",
       которого не хватало в предыдущих версиях с плоской заливкial.

4. **UX-улучшения относительно оригинала** (по итогам разбора customer journey
   пользователем, который прошёл kutkevich.ru как тайный покупатель):
   - Разделены неоднозначные CTA-кнопки на понятные пути
   - В B2B-блоках добавлены ценовые ориентиры и минимальные объёмы заказа
     (в оригинале их не было — это создавало трение для потенциального клиента)
   - Аккордеон в разделе "Для бизнеса" сделан по-настоящему сворачиваемым
   - Добавлена видимая валидация полей формы (подсветка ошибок, а не тихий сбой)

5. **Мобильная адаптация**: добавлено гамбургер-меню в хэдере, уменьшены заголовки
   на узких экранах (`text-3xl` вместо `text-4xl`/`text-5xl` по умолчанию),
   Hero перестроен из горизонтальной раскладки в вертикальную на мобильном.

## Урок на будущее

Для точного визуального совпадения с сайтом-референсом текстового описания и
скриншотов недостаточно — нужен исходный CSS/HTML-код (или хотя бы значения
через DevTools inspector), чтобы взять точные hex-цвета, названия шрифтов и
эффекты (градиенты, тени). Стоит запрашивать это сразу, а не после нескольких
неудачных итераций "на глаз".

## Как задеплоить

См. `README.md` — деплой на VPS (Node.js + PM2 + Nginx + Let's Encrypt),
домен покупается отдельно и привязывается A-записью. Файл `content.json`
хранится на диске сервера — правки через `/admin` не теряются между деплоями
(в отличие от serverless-хостингов типа Vercel, где файловая система временная).

## Деплой на Vercel (для демонстрации)

Для быстрого показа сайта заказчику/себе выбран Vercel вместо VPS:

1. Создан пустой репозиторий `yakdaria6-arch/meranti-site` на GitHub
2. Локальный git-репозиторий подключён через `git remote add origin` и запушен
3. В Vercel: Add New → Project → импорт репозитория `meranti-site` →
   Next.js определился автоматически → Deploy (без переменных окружения
   Telegram/admin — их можно добавить позже в Settings → Environment Variables)
4. Сайт опубликован: https://meranti-site.vercel.app/

Важно: пока `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ADMIN_PASSWORD` не
заданы в Environment Variables Vercel, форма заявки на сайте не отправляется
и `/admin` не работает — это ожидаемо для чисто демонстрационного деплоя.

## Как передать админку реальному клиенту

Сама админка (`src/app/admin/page.tsx`) уже полностью готова, ничего
дополнительно разрабатывать не нужно:

1. Задать `ADMIN_PASSWORD` в Environment Variables на хостинге
2. Дать клиенту ссылку `/admin` + пароль
3. Клиент сам меняет пароль через вкладку "Настройки" внутри панели

Важный нюанс: если сайт остаётся на Vercel, правки клиента через админку
могут слетать при каждом новом деплое (файловая система там временная,
`content.json` не сохраняется между билдами). Для клиента, который реально
будет сам вести контент, нужен VPS-деплой — там `content.json` хранится
на диске постоянно.

## Оценка рыночной стоимости такого сайта

Отдельным агентом собрана сводка цен на российском рынке (2025–2026) для
сайта такого уровня — см. файл `сайт премиум цены.md` в этой же папке.

## Пост-деплойные правки (мобильная адаптация и баги)

После публикации на Vercel пользователь тестировал сайт с телефона и
присылал скриншоты реальных проблем, которые не были видны в узком окне
разработки:

1. **Битые изображения** — 5 из 13 использованных Unsplash photo ID
   оказались недоступны (404): в Hero-слайдере, галерее, карусели
   ассортимента и в двух карточках кейсов внутри `data/content.json`
   (это отдельный источник данных от компонентов — легко забыть при
   правке). Все заменены на проверенные рабочие ID.
2. **Эмодзи-иконки не в стиле** — 🏨☕🏪💼 в блоке "Для кого мы работаем"
   выглядели разностильно на фоне золотой премиальной палитры. Заменены
   на кастомные inline SVG-иконки (тонкая линия, `currentColor` в золоте).
3. **Текст согласия на 152-ФЗ разъезжался** — прямые текстовые узлы внутри
   `<label className="flex items-start">` вели себя как отдельные
   flex-элементы вместо связного абзаца. Исправлено оборачиванием текста
   в `<span>`.
4. **Карусель ассортимента обрезалась без подсказки** — карточки на узком
   экране просто обрывались на середине следующей без визуального сигнала,
   что можно листать дальше; читалось как баг вёрстки. Сужены карточки
   (68vw вместо полной ширины) и добавлен fade-градиент у правого края
   контейнера, видимый только на мобильном (`sm:hidden`).

Урок: при переносе картинок из компонента в `data/content.json` нужно
проверять оба места — легко починить ссылку в одном файле и забыть про
дублирующуюся в другом.

## Незакрытая проблема: отступ в карусели ассортимента на мобильном (2026-08-02)

После нескольких итераций (px-8, px-10, distancer-блоки w-6, затем w-12)
пользователь на реальном телефоне продолжает не видеть отступа слева от
первой карточки в карусели ассортимента (`Assortment.tsx`), хотя:
- Скомпилированный CSS на сервере подтверждён напрямую (curl) —
  `.w-12{width:3rem}` присутствует, класс применяется в разметке
- HTML на сервере содержит правильную структуру (distancer div перед
  первой карточкой)
- Проблема не в кэше/деплое — пользователь закрывала вкладку полностью

Гипотеза, требующая проверки в следующей сессии: возможно, дело не в
отсутствии отступа как такового, а в том, что он недостаточно заметен
на глаз по сравнению с текстовым блоком заголовка секции выше (у которого
свой `px-4` контейнер) — создаётся оптическое ощущение "нет отступа" при
визуальном сравнении двух блоков с разной величиной паддинга. Нужно либо
выровнять отступы текстового блока и карусели по одной величине, либо
попросить у пользователя ещё один свежий скриншот с точной линейкой/
сравнением, чтобы не тратить итерации на изменение уже вроде бы рабочего
кода.

## Дополнительные материалы (запрошены 2026-08-02)

По просьбе пользователя запущены два фоновых агента:
1. Ресёрч рынка премиальных сайтов-визиток — цены, сроки изготовления,
   портрет клиента, каналы поиска заказчиков
2. Готовый оффер и продающие тексты (холодное сообщение, отклик на
   фриланс-биржах, вопросы для брифинга) на основе MERANTI как портфолио-кейса

Результаты — см. отдельные файлы, которые будут сохранены после
завершения работы агентов (ресёрч рынка и оффер для потенциальных клиентов).
